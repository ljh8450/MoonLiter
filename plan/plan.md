# 프로젝트 계획

## 현재 방향

- 초기 MVP는 React + Vite 기반 웹앱으로 출시한다.
- 배포 대상은 Cloudflare Pages다.
- 데이터, 인증, 이미지 저장은 Supabase를 우선 사용한다.
- 웹앱은 PWA로 설치 가능한 형태를 목표로 한다.
- iOS, Spring Boot, AWS EC2 배포는 초기 MVP 이후 확장 후보로 보류한다.
- 기존 Android 코드는 유지하지 않아도 되며, 정리 대상으로 둔다.
- 소셜 로그인과 자체 계정 로그인 기반으로 엽서 작성, 사진 업로드, 랜덤 전달, 오늘의 엽서 수신 흐름을 검증한다.
- 이메일/비밀번호 기반 자체 계정 로그인은 이메일 인증을 필수로 한다.
- 회원가입 시 전화번호 인증을 도입하고, 인증된 전화번호를 기준으로 중복 회원가입을 막는다.
- 엽서 작성과 수신은 로그인 기반으로 운영하되, 수신자는 발신자를 알 수 없는 익명성을 유지한다.
- 현재 스키마는 관리자 승인 기반 전달을 전제로 하며, 새 엽서는 `pending`으로 생성되고 `approved` 상태만 전달된다.

## 현재 구현 상태

- `frontend` 웹앱은 Supabase 소셜/이메일 로그인, 사진 1장 선택/검증/미리보기, Storage 업로드, 엽서 row 생성, 오늘의 엽서 RPC 호출, signed URL 이미지 표시를 구현했다.
- Supabase 마이그레이션은 `profiles`, `postcards`, `postcard_deliveries`, private `postcard-images` bucket, RLS/Storage policy, `assign_today_postcard()` RPC를 포함한다.
- 사진 없는 텍스트 엽서와 사진 포함 엽서 모두 같은 `postcards` 테이블을 사용한다.
- 관리자 승인 상태, 관리자 화면, 승인/반려 조작 UI는 구현되어 있다.
- 작성/수신 기록 목록, 신고, 사용자별 숨김/관심없음, 관리자 권한 관리, 사용자 정지는 구현되어 있다.
- 현재 사용자 정지는 기본 정지 기능이며, 전화번호 인증 기반 중복 가입 방지와 정지 횟수별 단계적 정지 기간은 후속 구현 범위다.
- PWA 서비스 워커는 배포 후 이전 `index.html`을 재사용하지 않도록 내비게이션 요청을 네트워크 우선으로 처리한다.
- Cloudflare Pages용 `_headers` 파일로 `index.html`, `sw.js`, manifest는 재검증하고 hashed assets는 장기 캐시하도록 정리했다.
- 고아 파일 정기 정리는 Supabase Edge Function과 운영 문서 기준으로 구현되어 있다.
- 반응은 아직 후속 범위다.
- 차단 기능, 계절 테마, 감성 태그는 현재 우선순위에서 제외한다.

## 목표 아키텍처

```text
React + Vite + PWA 웹앱
  -> Supabase Auth
  -> Supabase Postgres
  -> Supabase Storage
  -> Cloudflare Pages 배포
```

## 남은 플랫폼 계획

- 이메일 매직 링크, 이메일/비밀번호, 구글, 카카오 로그인 기반 Supabase Auth 연동을 유지한다.
- 이메일/비밀번호 로그인은 이메일 인증 완료 후 사용할 수 있도록 운영한다.
- 자체 계정 가입에는 전화번호 인증을 추가하고, 동일 전화번호로 여러 계정을 만들 수 없도록 제한한다.
- 작성/수신 기록, 관심없음, 사용자별 숨김, 신고, 관리자 승인 상태를 포함하는 데이터 모델을 유지한다.
- 사용자 정지는 누적 정지 횟수에 따라 1일, 7일, 30일, 1년, 영구 정지 순으로 적용한다.
- 정지 적용 시 앱 내부 알림으로 사용자에게 정지 사실을 알린다.
- 관리자 페이지 접근 권한은 별도 관리자 테이블을 기준으로 관리한다.
- 관리자는 새 엽서를 1차 검수해 승인/반려하고, 신고된 엽서는 사후 검토해 유지/숨김 처리한다.
- 관리자는 올바르지 않은 사용자 계정을 정지하거나 정지 해제한다.
- Cloudflare Pages 빌드/환경 변수 설정을 정리한다.
- 기존 Android 구현은 삭제해도 되며, Spring Boot 구현은 초기 MVP 경로에서는 제외한다.

## 초기 제품 우선순위

- 로그인 기반 감성 엽서 작성.
- 사진 업로드.
- 랜덤 엽서 전달.
- 오늘의 엽서 수신.
- 별도 엽서 보관/북마크.
- 로그인 사용자의 작성한 엽서 기록.
- 로그인 사용자의 받은 엽서 기록.
- 신고.
- 관리자 승인 기반 전달.
- 관리자 페이지.
- 신고, 숨김, 검수 상태 같은 기본 검수/관리 기능.

## 직후 구현 단위

- React + Vite 웹앱과 Supabase 기반 사진 업로드 MVP는 구현되어 있다.
- 인증 고도화, 작성/수신 기록, 신고, 관리자 승인 화면은 구현되어 있다.
- 다음 구현 단위는 자체 계정 로그인 보강, 전화번호 인증 기반 중복 가입 방지, 단계적 사용자 정지, 앱 내부 정지 알림, 운영 적용, 반응 같은 후속 운영 기능, reviewer 점검이다.
- 자체 계정 로그인 보강, 전화번호 인증 기반 중복 가입 방지, 단계적 사용자 정지, 앱 내부 정지 알림의 세부 계획은 `plan/26-05-18/account_integrity_and_suspension.md`에서 관리한다.

## 직후 구현 이후 순서

- 1단계: 운영 배포 적용.
  - Supabase 마이그레이션을 실제 프로젝트에 적용하고, Cloudflare Pages에 `frontend` 앱을 연결한다.
  - 배포 환경에서 Supabase 연결, 인증, Storage 접근, RPC 호출이 정상 동작하는지 확인한다.
- 2단계: 운영 데이터 기반 핵심 흐름 검증.
  - 실제 배포 환경에서 가입, 로그인, 엽서 작성, 관리자 승인, 오늘의 엽서 수신, 신고, 정지 흐름을 끝까지 확인한다.
  - 서비스 워커 캐시 전환 문제와 권한/RLS 문제를 함께 점검한다.
- 3단계: 반응 기능.
  - 받은 엽서에 대해 제한된 반응을 남길 수 있게 한다.
  - 반응은 자유 텍스트보다 `고마워요`, `위로됐어요`, `공감해요` 같은 고정 선택지를 우선 검토한다.
- 4단계: 앱 내부 알림 확장.
  - 정지 알림 이후 관리자 승인/반려, 신고 처리 결과, 받은 엽서 도착 같은 앱 내부 알림으로 확장한다.
  - 알림은 사용자별 읽음 상태를 관리할 수 있어야 한다.
- 5단계: reviewer 점검 및 MVP 안정화.
  - 권한, RLS, Storage 접근, 정지 사용자 제한, 관리자 기능, PWA 캐시를 점검한다.
  - 출시 전 결함과 운영 리스크를 정리한다.

## PWA 확장 계획

- 설치 경험을 개선한다.
  - 앱 이름, 아이콘, 테마 색상, 시작 URL, 표시 모드를 실제 서비스 기준으로 정리한다.
  - 모바일 홈 화면 설치 후 첫 진입 화면과 로그인 상태 복원 흐름을 확인한다.
- 오프라인/저품질 네트워크 대응을 확장한다.
  - 앱 셸은 캐시하되, 엽서 데이터와 인증 상태는 최신성을 우선한다.
  - 네트워크 실패 시 작성 중인 엽서 내용이 유실되지 않도록 임시 저장 후보를 검토한다.
- 앱 내부 알림과 PWA 알림의 연결을 검토한다.
  - 초기에는 앱 내부 알림을 우선 구현한다.
  - 이후 사용자 동의를 받은 경우 받은 엽서, 신고 처리 결과, 정지 안내 같은 이벤트를 푸시 알림 후보로 검토한다.
- 업데이트 전환 안정성을 유지한다.
  - `index.html`, `sw.js`, manifest는 재검증하고 hashed assets는 장기 캐시하는 현재 정책을 유지한다.
  - 새 버전 배포 후 이전 서비스 워커가 오래 남지 않도록 전환 안내 또는 자동 갱신 방식을 검토한다.
- 모바일 사용성을 점검한다.
  - iOS Safari와 Android Chrome에서 설치, 로그인, 사진 업로드, 카메라/앨범 접근, signed URL 이미지 표시를 검증한다.

## 현재 보류 항목

- 차단 기능은 우선 구현하지 않는다. 신고, 개인 숨김, 관리자 숨김, 사용자 정지로 기본 관리 흐름을 대응한다.
- 계절 테마는 MVP 우선순위에서 제외하고, 제품 감성 방향 또는 장기 UI 확장 후보로만 유지한다.
- 감성 태그는 당장 구현하지 않는다. 엽서 작성은 문장과 사진 중심으로 유지하고, 태그 기반 분류나 추천은 장기 후보로 보류한다.
